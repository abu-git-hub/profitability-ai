# Profitability AI

Интеллектуальный анализ рентабельности 12 образовательных программ (ОП) для руководства университета.
NEXTGEN IT WEEK 2026 · Track 01 · Case 01. Все данные вымышленные.

Загружает Excel → считает доход, ФОТ, прямые и накладные затраты, результат, рентабельность и себестоимость
студента по каждой ОП → находит аномалии → отвечает на вопросы ИИ-аналитика → моделирует «что если».

## Запуск (Windows / macOS / Linux, Python 3.10+; проверено на 3.13)

```bash
python -m venv .venv
.venv\Scripts\Activate.ps1        # Windows PowerShell;  macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Откройте http://localhost:8501. Загрузите `Profitability_AI_Test_Data.xlsx` в боковой панели или оставьте включённым
встроенный демо-файл (`data/Profitability_AI_Test_Data.xlsx`, тот же файл без правок).

Тесты: `python -m pytest -q tests` (19 проверок: независимый пересчёт «в лоб», 6 аномалий, сценарии, ИИ).

## Что умеет (по критериям жюри)

| Критерий | Реализация |
|---|---|
| Финансовая корректность | `engine.py`: методика кейса 1:1. Контрольные суммы: ФОТ **736 465 200 ₸**, накладные **500 000 000 ₸** (допуск ±1 ₸). Тест сверяет все 12 ОП с независимым пересчётом на чистом Python. |
| Data Quality | Проверка структуры файла + 6 правил по «Сырые_сигналы»: дубликат ID, неизвестная ОП, отрицательное, % > 100, пропуск, недопустимый период. Найдены все 6 (`SRC-004/901/902/903/904/905`) с типом, строкой Excel, причиной и действием. Автоматическая проверка изоляции: P&L без листа сигналов идентичен. Доп. проверки основных листов. |
| ИИ-аналитик | Вопросы на естественном языке; ответ = цифры из кода + формула + лист-источник + допущения. «Объяснить ОП»: 4–5 факторов с **точным разложением** отклонения от среднего по вузу (сумма вкладов сходится до тенге) и 3 управленческих варианта с эффектом и рисками. |
| Дашборд | 7 вкладок, фильтры по факультету и прибыльности, 6 графиков Plotly, drill-down до строк ФОТ/накладных, экспорт в Excel. |
| What-If | Любые ОП, −50…+50% контингента, допущения явно (грант, переменная доля ФОТ/прямых, тариф), до/после, перераспределение накладных, точка безубыточности. |
| Бонус | Прогноз набора по 3 годам с диапазоном и объяснением, почему 3 наблюдений мало. |

## Архитектура

```
Excel ─► engine.py ─► P&L + детализация + контрольные суммы + Data Quality + What-If + прогноз
                         │  (pandas, детерминированно; ИИ суммы НЕ считает)
                         ▼
                   ai_analyst.py ─► маршрутизатор вопросов → ответ с доказательствами
                         │              (опционально) Claude переформулирует; каждое число проверяется кодом
                         ▼
                      app.py (Streamlit + Plotly)
```

- `engine.py` — загрузка и проверка Excel, расчёт, контроль, аномалии, сценарии, прогноз.
- `ai_analyst.py` — ИИ-аналитик. **Локальный режим** (по умолчанию) работает без интернета и ключей:
  маршрутизатор вопросов + шаблоны поверх посчитанных данных. **LLM-режим**: при `ANTHROPIC_API_KEY`
  (или ключе в боковой панели) модель Claude (`claude-sonnet-5-5`, меняется через `PROFITABILITY_AI_MODEL`) получает
  только посчитанные факты и переформулирует готовый ответ; затем `unverified_numbers()` проверяет, что каждое число
  есть в расчёте. Если нет — показывается локальный ответ. Так LLM не может «придумать» бухгалтерские данные.
- `app.py` — интерфейс; `theme.py` — палитра, CSS, карточки (только оформление); `.streamlit/config.toml` — тема. `tests/` — тесты. `docs/PITCH.md` — сценарий демо и питча.

## Выбранная модель ИИ

Расчёты — код (pandas). Понимание вопроса и объяснения — локальный аналитик; при желании — Claude Sonnet через API
для более живых формулировок с обязательной проверкой чисел. Без ключа приложение полностью функционально.

## Допущения и границы решения

- Учебная модель: тенге, один год; доход начислен, а не оплачен; результат ≠ кассовый остаток; налог на прибыль,
  амортизация, стипендии, инвестиции, исследования не моделируются.
- «Сырые_сигналы» — только проверка качества, в P&L не входит.
- What-If по умолчанию — базовый вариант кейса (доход ∝ студентам, ФОТ и прямые неизменны, сумма накладных неизменна,
  students-центры перераспределяются, площадь и лаб. часы не меняются). Модель линейна, без порогов мощности.
- Финансовый результат не основание закрывать программу: нужны академические, кадровые, стратегические и социальные
  аргументы. Приложение это прямо указывает в объяснениях.
- Для реального внедрения нужны: фактические платежи, штатное расписание и фактическая нагрузка, учёт затрат по центрам,
  реальные площади, история набора 8–10 лет, утверждённая методика распределения накладных, роли и аудит.
